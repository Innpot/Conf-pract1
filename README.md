# Практическая работа №1 — вариант 20

Графический эмулятор UNIX-подобной оболочки на Python/Tkinter.
Все данные VFS хранятся и изменяются только в памяти. Исходный XML
не распаковывается и не перезаписывается. На диск пишется только журнал.

## Установка и запуск

Нужен Python 3.10+ с Tkinter. Сторонних Python-библиотек нет,
сборка не требуется. Проверка Tkinter: `python -m tkinter`.
В Windows Tkinter входит в стандартную установку Python;
в Linux может понадобиться системный пакет python3-tk.

Из корня репозитория:

```bat
run.bat
run.bat --vfs examples/vfs/deep.xml --log logs/session.xml --script examples/stage4.txt
scripts\test.bat
```

Linux/macOS: `sh run.sh` с теми же аргументами.
Универсальный запуск: `python -m src.main`.
Скрипты запуска поддерживают переменную `PYTHON` с путём к интерпретатору.

| Параметр | По умолчанию | Назначение |
|---|---|---|
| --vfs | examples/vfs/deep.xml | Физический путь к XML VFS |
| --log | logs/events.xml | Физический путь к XML-журналу |
| --script | отсутствует | UTF-8 файл стартовых команд |
| --help | — | Справка |

Пути с пробелами заключаются в кавычки. run.bat/run.sh переходят
в корень проекта. При прямом вызове модуля относительные пути считаются
от рабочей папки процесса. Настройки печатаются в консоль и окно.
Ошибки входных файлов дают сообщение в stderr и ненулевой код завершения.
Журнал и его временный файл не могут совпадать с VFS или стартовым скриптом.

## Работа в окне и команды

Заголовок содержит имя VFS; при запуске выводится корневой файл motd,
если он существует. Введите команду в нижнее поле и нажмите Enter.
В протоколе видны текущий каталог, ввод и результат. Парсер shlex POSIX
поддерживает одинарные/двойные кавычки и экранирование. Ошибки команд
и незакрытых кавычек выводятся как `Error: ...`, сессия продолжается.

| Команда | Поведение |
|---|---|
| `ls [-a] [-l] [--] [path]` | Содержимое каталога либо имя файла |
| `cd [path]` | Смена каталога; без аргумента — корень / |
| `clear` | Очистка окна, журнал сохраняется |
| `date [+FORMAT]` | Локальные дата/время ОС, формат Python strftime |
| `cal [[month] year]` | Текущий месяц, год или выбранный месяц |
| `chmod [-R] MODE path` | Изменение прав объекта или поддерева |
| `mv source destination` | Переименование или перенос |
| `exit` | Завершение приложения |

ls -a включает скрытые имена; -l показывает восьмеричные права;
флаги можно объединять (-al). `--` завершает разбор флагов.
Каталоги отмечаются /. Поддерживается один путь за вызов ls.
Виртуальные пути используют /, . и ..; подняться выше корня нельзя.
Неделя cal начинается с понедельника, допустимые годы — 1–9999.

chmod принимает 3–4 восьмеричные цифры (644, 0755) либо символьные
выражения `u+x`, `g-w`, `o=`, `a+r`, `u=rw,g=r,o=`. Без группы
изменяются u/g/o. Поддерживаются r/w/x; копирование прав между группами,
символ X и umask не моделируются. Права — метаданные; многопользовательский
контроль доступа не реализован. Проверять изменения можно через ls -l.

mv переносит объект внутрь существующего каталога либо задаёт новое имя.
Существующий файл заменяется; непустой каталог не заменяется.
Перенос корня, каталога внутрь себя и конфликты типов запрещены.
При переносе текущего каталога или его предка cwd обновляется.
После перезапуска изменения chmod/mv исчезают.

```text
cd /home/student/docs
ls -al
ls "with spaces.txt"
chmod u+x,g=r,o= notes.txt
mv notes.txt "new notes.txt"
mv "new notes.txt" /tmp
ls -l /tmp
date "+%Y-%m-%d %H:%M"
cal 2 2024
exit
```

Конвейеры, перенаправление, переменные, внешние программы и остальные
команды полноценной UNIX-оболочки в задание не входят.

## XML VFS

```xml
<?xml version="1.0" encoding="utf-8"?>
<vfs name="Example">
  <file name="motd">Добро пожаловать!</file>
  <dir name="docs" mode="755">
    <file name="text.txt" mode="644">Текст</file>
    <file name="data.bin" encoding="base64">AAEC/w==</file>
  </dir>
</vfs>
```

Корень — vfs, каталог — dir, файл — file. Имя — один компонент пути;
пустые и повторные имена, /, . и .. запрещены. mode по умолчанию:
755 для каталогов, 644 для файлов. encoding: utf-8 или base64.
Ошибочные XML, права и base64 отклоняются. Имя VFS берётся из name
корня, при отсутствии — из пути файла.

Фикстуры examples/vfs: minimal.xml — пустая VFS; files.xml — несколько
файлов, motd и двоичные данные; deep.xml — три вложенных уровня каталогов
с файлами, скрытым именем, пустыми папками и именем с пробелами.

## Скрипты и журнал

Стартовый скрипт — по одной команде на строку (UTF-8, BOM допустим).
Пустые строки и полнострочные комментарии # пропускаются.
Ошибка выводится, затем выполняется следующая строка; exit прекращает
скрипт и закрывает окно. Ввод и вывод отображаются в GUI.

Корень журнала — events. Каждый event содержит timestamp с часовым поясом,
user и дочерний command с исходной строкой. Пишутся успешные и ошибочные
вызовы, включая exit. Существующий журнал дополняется; некорректный
журнал не перезаписывается. Запись заменяет файл через временный соседний
файл. Один журнал предназначен для одной одновременно работающей сессии.

## Демонстрации и тестирование

```bat
scripts\config-demo.bat
scripts\config-errors.bat
scripts\vfs-demo.bat
scripts\vfs-errors.bat
scripts\commands-demo.bat
python -m unittest discover -s tests -v
```

config-* проверяют все параметры, включая пробелы и ошибки.
Каждый vfs-* запускает minimal, files и deep; vfs-errors также проверяет
отсутствующий XML. Окна открываются последовательно: закрывайте текущее
окно или вводите exit для перехода к следующему запуску.

examples/stage1.txt — интерактивная демонстрация прототипа;
stage3.txt — VFS и ошибки; stage4.txt — режимы основных команд;
stage5.txt — chmod/mv и ошибки. Для пошаговой защиты вводите строки вручную.
clear намеренно стирает предыдущий экран, но вызовы остаются в журнале.
В коммите этапа 1 ls/cd — заглушки; в итоговой версии — рабочие команды.

Тесты проверяют парсер, exit, CLI, продолжение скрипта после ошибки,
XML-журнал, VFS/base64, пути, команды, атомарность ошибочных mv,
обновление cwd и неизменность исходного XML. GUI-тест проверяет настоящие
Tk-виджеты: заголовок, ввод, вывод, clear, exit; без дисплея пропускается.
GitHub Actions запускает тесты на Windows с Python 3.12.

## Структура и функции

| Модуль | Назначение |
|---|---|
| src/main.py | main: настройки, VFS, журнал, окно |
| src/config.py | parse_args, validate_paths, script_lines, run_script |
| src/gui.py | Terminal: write, submit, run_line, run |
| src/shell.py | Shell: execute разбирает ввод; dispatch выбирает команду |
| src/event_log.py | EventLog: record добавляет событие, save пишет XML |
| src/vfs.py | Node; parse_node/children/data; VFS: resolve, node, motd |
| src/commands.py | ls/cd/clear/date/cal, проверка числа аргументов |
| src/mutations.py | chmod/mv, разбор прав, проверка назначения |
| tests/ | Тесты unittest |
| examples/ | XML VFS и стартовые сценарии |
| scripts/ | Демонстрации Windows и запуск тестов |

## Этапы в истории Git

1. feat(repl): GUI REPL, парсер кавычек, заглушки, exit.
2. feat(config): параметры, стартовый скрипт, XML-журнал.
3. feat(vfs): XML VFS в памяти, base64, motd и фикстуры.
4. feat(commands): ls, cd, clear, date, cal и проверки.
5. feat(mutations): chmod, mv, итоговые тесты и документация.

Просмотр этапов: `git log --oneline --reverse`.
